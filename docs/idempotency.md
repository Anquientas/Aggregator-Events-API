# Идемпотентность POST /api/tickets

## Назначение

Защита от дублирования билета при повторной отправке одного и того же
запроса клиентом — двойной клик, повтор после таймаута ответа и т.п.

## Как передать ключ

Необязательное поле `idempotency_key` в теле запроса:

    POST /api/tickets
    Content-Type: application/json

    {
      "event_id": "e1",
      "first_name": "Иван",
      "last_name": "Иванов",
      "email": "ivan@example.com",
      "seat": "A15",
      "idempotency_key": "любая-уникальная-строка-до-128-символов"
    }

## Возможные сценарии

| Сценарий | Ответ |
|---|---|
| Ключ не передан | Каждый запрос обрабатывается как новый (обычная регистрация без каких-либо проверок на повтор). |
| Ключ передан впервые | Обычная регистрация (Events Provider, сохранение билета, запись в outbox), `201` с данными билета. Пара «ключ и билет» сохраняется. |
| Тот же ключ, те же данные запроса | Повторный вызов НЕ создаёт новый билет и НЕ обращается к Events Provider повторно — возвращается `201` с тем же `ticket_id`, что и при первом запросе. |
| Тот же ключ, другие данные (другой `event_id`/`seat`/`email` и т.п.) | `409 Conflict`, новый билет не создаётся, ранее сохранённый результат не перезаписывается. |
| Events Provider вернул ошибку при первой попытке | Результат по ключу НЕ сохраняется — повторный запрос с тем же ключом будет обработан как новый, а не как конфликт. |

## Пример конфликта

Первый запрос с `idempotency_key = "abc"` и местом `A15` — `201`.
Повторный запрос с тем же `idempotency_key = "abc"`, но местом `A16` — `409`:

    {
      "detail": "Запрос с idempotency_key abc уже обработан с другими данными"
    }

## Технические детали

- Хранение — колонка `idempotency_key` (уникальный индекс, `NULL`-совместимый)
  прямо в таблице `tickets`, а не отдельная таблица: результат повтора — это
  и есть уже сохранённый билет, отдельно ничего сериализовать не нужно.
- Гонка одновременных одинаковых запросов («двойной клик» в буквальном
  смысле) закрыта на уровне БД через уникальный индекс + `SAVEPOINT`
  вокруг вставки: кто не успел — получает уже созданный билет победившего
  запроса, а не 500 или дубликат.
